# TASKFLOW · доска команды с уходящим временем

Таск-менеджер на одной странице. Задача прибита к конкретному часу календаря, а шкала под ней едет
влево час за часом. Поэтому задача, поставленная «на пару дней», подползает к красной линии дедлайна
со скоростью двух дней, и на экране сразу видно, у кого горит и кто перегружен.

Постановка целиком лежит в [ТЗ.md](./ТЗ.md).

## Что внутри

| Файл | Зачем |
|---|---|
| `index.html` | приложение, оно же главная страница сайта |
| `gsap.min.js` | анимация, лежит рядом и работает офлайн |
| `board.json` | общая доска команды, см. ниже |
| `taskflow.html` | та же доска одним файлом, GSAP вшит внутрь, удобно переслать в мессенджере |
| `build.py` | пересобирает `taskflow.html` из `index.html` |
| `.github/workflows/pages.yml` | публикация на GitHub Pages |

## Как открыть локально

Двойной клик по `taskflow.html`. Ни сервера, ни интернета не нужно.

Для разработки удобнее поднять статику, тогда работает и загрузка общей доски:

```bash
python3 -m http.server 8899
```

## Как выложить для команды

1. Создать репозиторий на GitHub и положить туда содержимое этой папки.
2. `Settings` → `Pages` → в поле **Source** выбрать **GitHub Actions**.
3. Запушить в `main`. Workflow `Deploy TASKFLOW to Pages` соберёт и развернёт.
4. Ссылка появится во вкладке `Actions` у завершившегося запуска и в `Settings` → `Pages`.

Команды для первого пуша, подставить свой аккаунт и имя репозитория:

```bash
git init -b main && git add . && git commit -m "TASKFLOW" && git remote add origin git@github.com:АККАУНТ/РЕПОЗИТОРИЙ.git && git push -u origin main
```

Публичный репозиторий даёт Pages бесплатно, но ссылка открыта любому, кто её знает. Приватный
репозиторий с Pages требует платного тарифа Organization.

## Про общий доступ: почему у каждого своя доска и как это исправить

GitHub Pages отдаёт статический файл. Задачи лежат в `localStorage` того браузера, где их создали.
Поэтому по умолчанию у Андрея своя доска, у Оксаны своя, а кнопка «Опубликовать board.json» кладёт
в репозиторий снимок доски того, кто её нажал. Чужие задачи так не появятся.

Есть два способа сделать доску общей.

### Способ 1, без сервера и без регистраций

Каждый жмёт «Ещё» → «Экспорт JSON» и присылает файл. Один человек жмёт «Ещё» → «Добавить из файлов
коллег», выбирает сразу все присланные файлы, и задачи сливаются в одну доску. Ничего не затирается:
по каждой задаче побеждает более поздняя правка, удаления тоже переносятся. Дальше «Опубликовать
board.json» и коммит, чтобы у всех была одна отправная точка.

Годится, когда доску сводят раз в день. Минус очевиден: это ручная работа.

### Способ 2, живая синхронизация · рекомендуется

Задачи всех участников попадают на доску сами в течение восьми секунд. Нужно поднять крошечное
хранилище. Готовый файл сервера лежит рядом: `worker.js`, это Cloudflare Worker. Бесплатного тарифа
хватает с большим запасом.

**Что сделать, по шагам.**

1. Завести аккаунт на `dash.cloudflare.com`, бесплатный.
2. В левом меню `Workers & Pages` → кнопка `Create` → вкладка `Workers` → `Create Worker`.
   Имя, например `taskflow-sync`. Нажать `Deploy`, потом `Edit code`.
3. Стереть код-заготовку, вставить целиком содержимое `worker.js` из этого репозитория,
   нажать `Deploy`.
4. Создать хранилище: левое меню `Storage & Databases` → `KV` → `Create Instance`,
   имя `taskflow-board`.
5. Вернуться в воркер → `Settings` → `Bindings` → `Add` → `KV Namespace`.
   В поле `Variable name` написать ровно **BOARD**, в поле namespace выбрать `taskflow-board`.
6. Там же `Add` → `Environment variable`, имя ровно **TEAM_KEY**, значение это общий пароль команды,
   любая строка подлиннее. Нажать `Encrypt`, затем `Deploy`.
7. Скопировать адрес воркера, он вида `https://taskflow-sync.ВАШ-ПОДДОМЕН.workers.dev`,
   и дописать в конце `/board`.

**Что сделать каждому в команде.** Открыть доску → «Ещё» → в разделе «Общая доска команды» вставить
этот адрес и общий пароль → «Проверить связь» → «Включить». В шапке появится зелёная точка
«синхронно». Всё, задачи видны всем.

Тот, кто включит синхронизацию первым, зальёт в пустое хранилище свою доску, остальные подтянут её
и добавят своё.

**Как это устроено внутри.** Раз в восемь секунд приложение читает общую доску, свои правки
отправляет через полторы секунды после последнего изменения. Слияние идёт по времени правки: по
каждой задаче побеждает та версия, которую изменили позже. Удаления хранятся отдельным списком,
поэтому удалённая задача не воскресает с чужого компьютера. При одновременной записи сервер отвечает
кодом 409, приложение сливает свежую версию и повторяет отправку.

**Честные границы.** Пароль лежит в браузере у каждого и передаётся заголовком, это защита от
случайного прохожего, а не от целенаправленного взлома. Доска у всех общая целиком, разделения прав
по людям нет. Если понадобится вход по личным учёткам и права на уровне ролей, это уже полноценный
бэкенд, скажем Supabase, и отдельная задача.

## Как пользоваться

- **Создать задачу:** плавающая кнопка справа внизу, кнопка в шапке, кнопка внутри любого столбика
  пула или клавиша <kbd>N</kbd>.
- **Поставить в план:** перетащить карточку из пула на линию сотрудника в нужный час. Прилипает к
  границе часа, при перетаскивании показывается точное время.
- **Снять с плана:** перетащить карточку с линии обратно в столбик пула.
- **Клавиши:** <kbd>←</kbd><kbd>→</kbd> двигают выбранную задачу на час, с <kbd>Shift</kbd> на шесть.
  <kbd>1</kbd>..<kbd>6</kbd> перекидывают на линию, <kbd>0</kbd> в пул, <kbd>Del</kbd> удаляет,
  <kbd>⌘Z</kbd> отменяет.
- **Посмотреть, как это едет:** переключатель «время» в шапке. На ×3600 час доски проходит за
  секунду. Пока ускорение включено, часы в шапке краснеют и подписываются «ускорено», чтобы никто
  не принял симуляцию за настоящее время.

## Ограничения

Данные лежат в localStorage браузера. Чистка данных сайта стирает доску, поэтому раз в неделю стоит
жать «Экспорт JSON». Комментариев, вложений и истории изменений нет, это требует бэкенда.
